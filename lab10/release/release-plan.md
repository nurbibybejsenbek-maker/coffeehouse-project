## Орналастыру мен релизді бөлу

Код продқа кіруі релиз емес.

1. CI standalone артефактісін шығарады. Бұл деплой дайындамасы.
2. Staging-ке артефакт қойылады, flag өшірулі. Қонақ ескі мінезді көреді.
3. Сейсенбі 15:30-да Назгүл go айтқан соң flag қосылады немесе трафик жаңа нұсқаға ауады. Міне, релиз.

Canary осы сайттың масштабында пайыздық флот емес. Алдымен админ сессиясы (қызметкер), 15 минут, содан кейін барлық қонақ. Blue-green: `coffee-blue` және `coffee-green` екі compose жобасы, сыртқы порт тек біреуінде. Ақау болса порт ескі жобада қалады.

## RACI

R — орындайды, A — бекітеді, C — кеңеседі, I — хабардар.

| Қадам | Назгүл | Элеонора | Нұрбиби |
|---|---|---|---|
| Go / no-go | A | C | C |
| Артефактіні қою және кері қайтару | A | I | R |
| Басты бет, мәзір, тапсырыс, брондау smoke | C | R | C |
| Админ кіру smoke | A | C | R |
| Тапсырыс берушіге хат | R | C | I |
| Қонаққа қысқа мәтін | A | R | I |
| Уақытты DORA журналына жазу | R | I | C |

## Релиз чек-парағы

### Бір күн бұрын (Назгүл)

- [ ] main-де `lint-and-test`, `build`, `security-scan` жасыл.
- [ ] OSV және Trivy есебінде осы релизбен келген жаңа CRITICAL жоқ. Ескі базаның өзі релизді тоқтатпайды, жаңасы тоқтатады.
- [ ] Шығатын SHA және кері қайтаратын алдыңғы жасыл SHA жазылған.
- [ ] Сұлба өзгерісі жоқ, не тек expand (баған өшірілмейді).
- [ ] Тапсырыс берушіге хат кетті.
- [ ] Қонақ мәтінін Элеонора дайындады.

### Терезе ашыларда, 15:15 (Нұрбиби)

- [ ] SQLite көшірмесі алынды: `prisma/backups/dev.db.YYYYMMDDHHMM`.
- [ ] Staging smoke өткен.
- [ ] Кезекші үшеуі де желіде.

### 15:30–16:10

- [ ] Назгүл: go.
- [ ] Нұрбиби: таңдалған SHA орнады (төмендегі команда).
- [ ] Элеонора: басты бет ашылады, мәзір тізімі көрінеді, тапсырыс формасы жіберіледі, брондау сақталады.
- [ ] Нұрбиби: админ логин ашылады, асүй тізімі жүктеледі.
- [ ] Flag болса, әуелі қызметкерге, 15 минуттан кейін қонаққа.
- [ ] 16:10-ға дейін қате жоқ. Назгүл релизді жабады.

### Кейін, 30 минуттың ішінде

- [ ] Элеонора қонақ мәтінін жариялайды (өзгеріс көрінсе) немесе «қысқа жаңарту болды» деп жабады.
- [ ] Назгүл тапсырыс берушіге нәтижені жазады: шыққан SHA, не өзгерді, инцидент болды ма.
- [ ] Журналға уақыт түседі: терезе ашылды, трафик ауысты, smoke бітті. Келесі DORA есебі осы уақыттан lead time пен жиілікті көреді.
- [ ] Сәтсіз болса, релиз жабылмайды. [Кері қайтару чек-парағы](rollback-checklist.md) ашылады, сағат инцидент анықталған минуттан жүреді.

## Орнату командасы

Репозиторий түбінде, продқа баратын SHA:

```bash
git fetch origin
git checkout <release-sha>
docker compose build app
docker compose up -d --no-deps app
```

Бұл команда дерекқорды өшірмейді. `prisma db push --accept-data-loss` релиз терезесінде іске қосылмайды.

Релизден кейін:

> Шықты: `<sha>`. Не өзгерді: …. Smoke өтті / өтпеді. Кері қайтару болды ма: жоқ / иә, `<previous-sha>`, қалпына келтіру N минут.

## Қонаққа мәтін

Қазақша, Элеонора жариялайды:

> CoffeeHouse сайты бүгін сағат 15:30–16:30 (Алматы) аралығында қысқа уақытқа жаңаруы мүмкін. Тапсырыс не брондау кетпесе, бірнеше минуттан кейін қайталаңыз.

Орысша:

> Сайт CoffeeHouse сегодня с 15:30 до 16:30 (Алматы) может ненадолго обновляться. Если заказ или бронь не отправились, повторите через несколько минут.

## Hotfix

Сайт ашылмаса, freeze терезені тоқтатпайды. Назгүл инцидентті жариялайды, сол чек-парақ қысқарады, MTTR сағаты сол минутта басталады. Түзету де PR арқылы, CI жасыл, бір бекітумен. Әкімші тікелей push-ты тек ревью беруге ешкім үлгермеген және сайт жатқан кезде ғана қолданады.
