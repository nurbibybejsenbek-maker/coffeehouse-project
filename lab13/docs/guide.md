# PM ассистентін пайдалану нұсқаулығы

CoffeeHouse. Команда: Естемес Назгүл (PM), Жаукарбекова Элеонора (BA), Бейсенбек Нұрбиби (SA). Құжаттың иесі, жіберілген мәтін үшін жауапты адам: Бейсенбек Нұрбиби. Модель автор емес.

## Қай жұмысты автоматтаймыз

Апталық статус: өткен екі спринттің мақсаты, throughput, ашық және ескірген тапсырма, бөгет, репозиторий санағы. Кіріс — осы репозиторийдегі нақты дерек: `lab09` тақтасы мен `git log`. GitHub API сол терезедегі коммит санын растайды. Спринт тарихы 2026-10-19 мен 2026-10-30 аралығында симуляцияланған. Сол терезеде коммит 0. Қарашадағы коммиттерді спринт жұмысы деп жазбаймыз.

Санды Python жинайды. Модель сан шығармайды. Осы аптаның прогоны модельге бүкіл BRIEF-ті беріп, статус мәтінін сұрады. Нәтиже `docs/verification.md` ішінде: нобай жіберілмейді.

## Промпт үлгісі

Файл: `prompts/status_v1.txt`. Бес бөлік, команда бұны бос чатқа қайта жазбайды.

1. Контекст. Пайдаланушы хабары — тек `output/brief.md`. Чат тарихы мен ескі есеп кірмейді.
2. Рөл. PM хатшысы. Шешім қабылдамайды, адамды бағаламайды, мерзім болжамайды, заң жазбайды.
3. Шектеу. BRIEF-те жоқ сан, id, себеп жоқ. «Шамамен» жоқ. Git коммиті тапсырманың Done болуы емес.
4. Формат. Алты тақырып, сол ретпен: Спринт 1, Спринт 2, Ашық тапсырмалар, Тәуекелдер, Келесі әрекет, Дереккөз.
5. Сапа. Әр санның жазылуы BRIEF-пен бірдей. Келесі әрекеттің мерзімі жоқ болса, «дерек жоқ».

Үлгіні өзгертсек, ескі файлды өшірмейміз. Жаңасы `status_v2.txt`. Қай файлмен шақырылғаны есептің ашып көрсету жолында тұрады.

## Тексеру ережесі

Бірде-бір сан және бірде-бір сілтеме тексерілмей құжатқа кірмейді. Автосүзгі (`pm_assistant/check.py`) тек бөтен санды, бөтен id-ді және бағалау сөзін қарайды. Ол түсірілген метриканы көрмейді. PM BRIEF-тің әр санды жолын нобайдан іздейді, тапса жазылуын салыстырады, таппаса «түсірілген» деп журналға жазады. Журнал толмай тұрып есеп тапсырыс берушіге кетпейді.

Жіберілген құжат үшін жауап модельде емес, құжатты жіберген адамда.

## Модельге не жіберілмейді

Жергілікті Ollama-ға да, сыртқы API-ге де мыналар кетпейді:

- дербес дерек: ЖСН, құжат нөмірі, телефон, email, мекенжай, төлем картасы, қонақтың аты;
- коммерциялық құпия: келісімшарт, маржа, жарияланбаған баға, клиент тізімі;
- құпия конфигурация: `.env`, `DATABASE_URL`, токен, жеке кілт, git remote ішіндегі `https://токен@` жолы;
- тапсырыс берушінің жабық репозиторийі мен жабық код;
- адам туралы баға: кім кінәлі, кім нашар істеді.

Скрипт пакеттен құпияға ұқсас жол тапса, модельге шақырмай тоқтайды. `GITHUB_TOKEN` тек орта айнымалысынан оқылады, ол BRIEF-ке жазылмайды. GitHub API-ге тапсырма мәтіні кетпейді, тек коммит санағы сұралады.

Осы жобаның команда есімі студенттердің өз аты. Ол жергілікті модельге BRIEF ішінде барады. Сыртқы коммерциялық чатқа сол BRIEF жіберілмейді.

## Қайда жергілікті 3B моделі жеткілікті

Осы прогон, `qwen2.5:3b`, кіріс 4834 токен. Қысқа жолды көшіру жеткілікті болды: ашық тапсырманың id-і, күйі, жасы, ақаудың бір сөйлемі. Статус есебі жеткіліксіз болды: throughput, Cycle Time, пайыз, ретро нәтижесі және коммит санағы түсіп қалды, CH-111 туралы дәлдеу жоғалды. Үлкен коммерциялық модельмен қатарластырып өлшеген жоқпыз, сондықтан «неше пайыз нашар» деген сан жоқ. Өлшенгені: осы ноутбук моделі жіберілетін статус мәтінін шығармады.

12-аптадағы қысқа жіктеу (`publish` / `hold` / `reject`, бір пікір) сол модельге сыйған жұмыс. Ұзын есеп сыймады.

## Кесте

Жергілікті іске қосу:

```bash
cd lab13
python3 scripts/run_status.py
```

Факті ғана, модель жоқ:

```bash
python3 scripts/run_status.py --facts-only
```

GitHub Actions (`.github/workflows/pm-status.yml`) дүйсенбі 04:00 UTC, яғни 09:00 Asia/Almaty, фактіні жинап артефакт қылады. Runner-де Ollama жоқ, сондықтан workflow нобай жазбайды. Нобай ноутбукте ғана.

2026-11-27 күні ашық беттен оқылған мәтін: әл-Фараби атындағы ҚазҰУ, «Жасанды интеллект технологияларын қолдану туралы ереже», https://farabi.university/students/34?lang=kz. Бұл CoffeeHouse титулындағы оқу орны екені көрсетілмеген. Өз ЖОО-ның құжаты келсе, төмендегі сілтемелер соған ауысады.

Сол жария мәтіннен осы жұмысқа алынғаны:

- 5.11. GenAI қолданылса, құралдың аты, сілтемесі, мақсаты, міндеті және сұрау мәтіні көрсетіледі. Әдебиет тізімі болмаса, нұсқау жұмыспен бірге сақталады. Біздегісі: Ollama, `qwen2.5:3b`, шақыру уақыты есептің басында, мақсат статус нобайы, сұрау `prompts/status_v1.txt`.
- 5.14. Нәтиже үшін жауапкершілік білім алушыда. Техникалық шекті білу және дұрыстығын тексеру сол адамда.
- 6.1. Қорытындыны автор өзі жазады. «Таза үнем бар ма» деген сөйлемді модель жазған жоқ.
- 6.2. Өндіруші, нұсқа және пайдалану күнінсіз GenAI қолдану адалдықты бұзады. Өндіруші: Alibaba Cloud, Qwen тобы, жергілікті көшірме `qwen2.5:3b`. Күні: 2026-11-27.
